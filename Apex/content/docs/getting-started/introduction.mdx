APEX is a cloud-based change management platform built for enterprise IT teams. It gives you structured workflows for managing change requests, project requests, and deployments — with built-in approvals, audit trails, and real-time notifications.

## Who Is APEX For?

APEX is designed for IT operations teams that need to:

- Control how changes reach production environments
- Pass compliance audits (SOC2, ISO 27001, ITIL)
- Reduce change-related outages
- Give stakeholders visibility into IT operations

It works best for teams of 5–500 people. Smaller teams use it to build good habits early. Larger teams use it to scale discipline across departments.

## Core Concepts

Understanding three concepts will take you through 90% of APEX:

### Change Requests

A **Change Request** is a formal record for any proposed change to your IT environment — a deployment, a configuration change, a database migration, or a process update. Every change request goes through a lifecycle:

`Draft → Submitted → Under Review → Approved → Scheduled → In Progress → Completed`

You can also cancel or roll back at any point.

### Projects

**Projects** group related work. A project might represent a feature initiative, a migration programme, or a compliance remediation. Projects contain tasks and are linked to project requests.

### Deployment Requests

A **Deployment Request** tracks the act of deploying to a specific environment (Dev, Staging, Production). Deployments can be linked to approved change requests, giving you a complete chain from change proposal to production impact.

## Navigation

APEX has five main sections:

| Section | Purpose |
|---------|---------|
| **Dashboard** | KPIs, recent activity, pending approvals |
| **Change Requests** | Create, review, and approve changes |
| **Projects** | Manage project lifecycle and tasks |
| **Deployment Requests** | Track deployments and link to changes |
| **Admin** | Users, departments, roles (TenantAdmin only) |
